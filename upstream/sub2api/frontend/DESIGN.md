# 星桥 UI 设计规则

## 侧栏与内容区对齐

- 用户端所有页面的标题顶边使用同一壳层上留白：桌面 20px、窄屏 12px；首个内容块与标题的间距以密钥页为准，桌面 12px、窄屏 8px。页面自身的列表、表单和图表间距不受这条标题规则影响。
- 底部对齐以侧栏账号／帮助按钮区的底边与主内容卡片底边为基准，而非窗口底边。两边下方必须保留相同留白，不能通过取消留白实现对齐。
- 两侧统一使用 --xq-bottom-gutter：桌面 24px，700px 以下窄屏 18px。单屏密钥列表直接对齐；短内容的 AI 线路和充值页末尾区域填满剩余高度；长页面在主内容滚动到底部后对齐，局部横向滚动不受影响。
- 验收须实际测量页面标题和首个内容块与密钥页的顶边差异，以及 .user-sidebar-actions 与内容末尾卡片的 getBoundingClientRect().bottom；差值均不超过 1px。还需验证留白非零、桌面和窄屏。仅检查滚动容器高度不构成视觉对齐证据。

## 筛选选择框

- 用户端筛选框以使用记录页四个筛选框为视觉基准：使用共用 `Select`，深色填充 `--xq-depth`、1px `--xq-border` 描边、8px 圆角、`--xq-text` 文字和 `--xq-secondary` 下拉箭头。不要混用亮灰填充与灰色描边。
- 悬停和键盘焦点用 `--xq-accent` 强调边框，焦点须有清楚可见的轮廓；错误、禁用状态保留各自语义。弹出列表沿用品牌色，文字与背景保持可读对比。
- 页面可以按信息密度调整宽度、内边距和高度，窄屏允许换行；基础颜色、描边粗细、文字、箭头与圆角不得各页另写一套。管理端浅色主题沿用其自身配色，不强制套用用户端深色值。

## 刷新操作

- 全局手动刷新按钮统一采用「刷新图标 + 刷新文字」，以密钥页工具栏为视觉基准。适用于用户端、管理端、弹窗、详情面板和错误恢复入口。
- 使用项目 Icon 的 `refresh` 图标，放在文字左侧；文字使用 `t('common.refresh')`，中文显示「刷新」。不得只显示图标、只显示文字，或仅通过 tooltip、aria-label、sr-only 提供文字。
- 使用现有 `btn btn-secondary` 次要按钮体系，图标与文字水平排列并保持间距；深色用户端沿用深色底、细描边和圆角。窄屏仍保留图标和文字，允许工具栏换行，不裁切成固定宽度的图标按钮。
- 保留刷新范围、事件、加载和禁用逻辑；加载动画作用于图标，文字持续可见。提供键盘焦点反馈。
- 自动刷新开关、重试、同步、重新授权和刷新凭据属于不同操作，保留准确的动作名称，不因复用刷新图标而改称普通「刷新」。
- 新增或修改刷新入口时检查默认、加载、禁用及窄屏状态，避免再次出现两套表达。

### 可见性与验收硬规则

- 刷新图标必须有实际 SVG 路径且保持可见，不随 flex 布局收缩；禁止通过页面或窄屏 CSS 隐藏刷新图标。Icon 输出的 data-icon=refresh 用于识别该语义，工具栏隐藏装饰图标的样式必须排除它。
- 桌面和 375px 窄屏均须同时看到左侧刷新图标和右侧「刷新」文字；默认、加载、禁用态都必须保留这两项。加载动画仅作用于图标。
- 单元测试不能把刷新图标全部 stub 掉：至少在使用记录页回归测试中验证真实 SVG 路径。发布验收须检查实际 DOM、计算样式和页面截图，不能以 commit、HTTP 200 或文字存在代替视觉验收。
- 若用户截图与最新资源不一致，先核对页面加载的资源版本及实际渲染，不得未经验证直接归因于浏览器缓存。

## 我的密钥：单屏列表

- 密钥工作区固定为视口剩余高度，顶部搜索、筛选和操作合并为紧凑工具栏，API 端点使用次级单行信息；窄屏自然换行。
- 页面内容不纵向滚动，分页固定在工作区底部。根据可用高度和实际行高自动计算每页条数，沿用服务端分页、搜索和排序，不仅隐藏超出的行。
- 窄屏保留紧凑表格，允许表格横向滚动查看全部列，不转成撑长页面的多张卡片。
- 行内线路菜单锚定按钮下方，按下方剩余空间限制高度，搜索区固定、选项内部滚动。改变窗口尺寸时关闭旧浮层，避免错位。
