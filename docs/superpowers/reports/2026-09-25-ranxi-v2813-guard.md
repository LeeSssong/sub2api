# #71 凭证守护安全与恢复候选

范围：基于 6b8a1e7241 的独立 `codex/ranxi-v2813-guard`。仅本地代码、测试、提交；没有推送、访问生产、发送真实令牌/密码、模型请求或 Bark 通知。

## 行为

- 自动巡检与手动重登使用 PostgreSQL transaction advisory lock 跨实例互斥，并保留本进程互斥。没有仓储锁能力时运行失败关闭。
- 凭据写回要求账号 `updated_at`、完整 credentials、status、schedulable、error_message 与发起请求的快照一致，且仍是有效 OpenAI OAuth 母账号。只合并 access_token/refresh_token/id_token/expires_at/token_type；其他凭据设置保持。写回及 scheduler outbox 原子提交。
- 不再调用通用 ClearAccountError/SetAccountSchedulable，不清理任何其他规则的冷却状态。
- 配置同时 Enabled + RestoreSchedulable 时，连续明确认证失败达到阈值，可通过 CAS 将原本 active、schedulable、没有错误和有效冷却/到期限制的账号标记为守护自有隔离。新表 `account_token_guard_ownership` 持久化该次写入的精确账号版本。
- 后续成功探活或重登只恢复仍与持久化所有权版本相同的自有隔离；人工修改、质量规则更新、新凭据等其他写入使所有权失效。守护自身的 CAS 凭据更新可延续仍有效的所有权。恢复也重新检查其他冷却及账号到期限制。
- 历史来源不明的 error/手工停用/质量隔离永不被据文字认领或自动恢复。跳过恢复原因写入当前探活展示信息；手动重登可安全更新凭据，但成功并不代表恢复调度。
- 仅信任结构化、精确匹配的认证错误码；第三方消息正文不作为认证证据，也不写入状态、事件或返回错误。测活端点 HTTP 401 本身不能证明目标令牌失效，按临时故障处理。所有凭据请求及 Bark 请求禁止跟随重定向。
- 探活中间写入不再把 fail_streak 清零；每轮只更新采样账号，不删除其他账号的历史，从而保留阈值及轮转公平性。成功/临时错误终止连续认证失败计数。
- 配置重载用于每次运行。密码空白保持原样；掩码对应不到旧账号时恢复为空，由校验拒绝，不会把 `********` 当成真实密码。

## 加密接线

父任务须在构造服务、启动/暴露接口前调用 `SetEncryptor(existing SecretEncryptor)`。保存时整个配置以 `encrypted:v1:` 封装后加密，涵盖密码、MFA、请求头及 Bark Key；公开响应继续掩码，缺少解密器无法读取加密配置。为兼容已有测试/部署，未注入加密器的服务仍允许明文保存，生产接线不可省略。历史明文配置允许读取，下一次显式保存加密；不在读取时无条件写回，避免覆盖并发管理员更新。

## 迁移

新增 `254_token_guard_recovery_ownership.sql`，只创建账号所有权表，无旧表列变更。父任务负责与其余新增迁移统一应用在线锁/超时策略。本测试未证明生产不停机发布。

## 边界

所有权基于应用账号写入均更新 updated_at 的既有协议。数据库连接丢失时 advisory lock 自动释放，账号 CAS 仍防止旧快照覆盖；无法撤回已经发往可信重登端点的请求。端点必须管理员明确配置且可信。没有给旧版任意错误赋予自动恢复权限，没有宣称旧错误都能自愈。
