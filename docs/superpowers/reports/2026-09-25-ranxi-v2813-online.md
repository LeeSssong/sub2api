## 来源及迁移

- 基线：`origin/main` = `50c1376e754bf81517b7c1e4fadd9073decf16c6`。
- 既有 SQL（包含 325）字节保持不变；仅修改本次新增 SQL。
- 精确迁移集合：`9bdf03d2fe484a6cb2ff8a1cc9fb690cc523d3c17f6a142a9775daa7c8503f6b` → `5b011a1ade72118f5a69c1afaa728f5aa5060b27444b199362483a27a03a08df`。
- Controller、host、发布成功后的回滚分别限制此配对，保留既有 v0.2.8 配对。不得更改 SQL 后继续复用此目标哈希。
- 新事务 SQL 使用 `SET LOCAL lock_timeout='100ms'`、`statement_timeout='2s'`，worker/all 启动也受约束。原 migrate-only 的 100ms/2s 和总 10 分钟保持。
- 247 普通唯一索引移到 252 `CREATE UNIQUE INDEX CONCURRENTLY`。runner 对本索引设置 100ms 锁等待/60s 执行预算；先检查重复账号质量规则，再清理 INVALID 旧索引后重试。不会删除冲突业务数据。连接参数退出时重置。
- migrate-only 成功或失败都读取数据库 `schema_migrations` 收据计算真实集合哈希；自动回滚保留实际 schema。中断发生在迁移执行/收据读取之间时 fail-closed 留检查点，禁止推断数据库已回滚。

## 流量与后台任务

- 新参数 `--drain-mode retain`：本融合必选。切流 300 秒后仍有 ESTABLISHED/CLOSE_WAIT 时保留旧 API，不发送强杀，保留 drain marker 阻止下一次发布。
- 连接提前清空时：retain 模式只发 SIGTERM，让应用清理异步用量/采集队列；若尚未退出，记录 retained 并保留 marker。普通默认 force 模式仍在 300 秒总窗口内强制终止，但提前排空时使用剩余时间优雅停止，不再立即 SIGKILL。
- 未添加自动清除 retained marker 的计时器。后续需在发布锁下核对当前路由、旧实例已退出/完成清理及旧实例身份，再清除对应 marker。旧镜像、配置及回滚入口保持。
- worker 是同名 singleton 顺序重建，Compose 显式 60s stop grace；不启动双 worker。既有就绪、镜像身份及失败恢复保留。
- Caddy 所有主 API 代理设置 `stream_close_delay 24h`。它是明确的 **24 小时**升级连接保留上限，不是永久连接保证。
- `bps_image_slot_routes` 共享片段用于公共站点及内部 `:8081`，按 `/api/bps-images/blue/*`、`/green/*` 固定代理原槽，原路径不重写；旧无槽 URL 仍走活动实例。发布/回滚的活动路由检查只排除这两个精确 callback 路由，仍对其余活动 upstream 做唯一性校验。

## 发布前仍需满足；当前不声称可直接上线

- 未查询生产/测试站，没有线上证据、制品 digest 或线上耗时。
- Host 在任何迁移前检查 **live Caddy JSON 已具备 >=24h stream_close_delay**，还检查实际切流 Caddyfile及 worker 60s 配置；不满足就拒绝。仅把 delay 写进新配置不能追溯保护旧代理 handler 上的 WS，因此不能用本次 reload 冒充既有连接已安全。首次配置准备仍需针对实时连接状态安排并验证。
- 未用旧生产二进制在新 schema 上完整运行；已证明基线列/类型保留及迁移可重跑，未把这一证据夸大为完整业务回归。
- 24h 后仍活跃的 WS 超出代理保留上限；要求无限连接寿命时此实现不足，应在上线前另行设计/批准。
- 迁移部分失败会留下可兼容的扩展；收据哈希若不等于任一已批准完整集合，后续发布 fail-closed，需检查实际收据再准备受审恢复/继续方案，不能强改状态文件伪装成功。
- 未修改后端请求/采票运行模块。原实例停止前后台租约、凭据所有权、回调生命周期和账务队列正确性依赖融合主任务的对应实现。
