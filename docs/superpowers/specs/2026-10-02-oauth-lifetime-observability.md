# OAuth lifetime observations

Approved by the user on 2026-10-02: implement the proposed lifecycle, load, quality and reporting observations. Lifetime means strictly the first successful state probe until the first subsequent unsuccessful (degraded) state probe. Network failures, unknown results, BPS switches, quota, expiry and manual disable never terminate this metric. Recovery never resets the first interval. The primary metric is account-wide; additional model/protocol/probe-version series are separate explanatory breakdowns, not a redefinition or reset of lifetime. An account record is one use episode; a keyed upstream identity links reimports without pooling episodes.

Reuse native accounts, usage_logs, scheduled tests and scheduler; no parallel billing or management UI. Critical account/rule/result changes are archived transactionally, without cascading deletion. Observe manual and scheduled state probes at the common probe boundary. Runtime slot/selection/outcome observations use a bounded asynchronous queue, expose drops/errors, and never propagate telemetry errors into requests. Usage amounts remain copies of native usage facts for analysis only. No tokens, tickets, request/response text, email, raw upstream errors or client IPs in observation payloads. Account names are resolved for authorized reports only.

Tables: keyed subject/episode registry, append-only event history, probe lifetime summaries, usage minute facts, runtime slot intervals and recorder health. Keep events/slots for 90 days, minute facts for 180 days; preserve compact lifetime summaries. Retention is bounded and only applies to observation tables. Missing runtime data and open slots are explicitly incomplete, never treated as zero occupancy.

Outputs: SQL lifetime/cohort report, account timeline, per-model/protocol use and occupancy minute reports, quality/configuration timelines and telemetry coverage. No causal claims from observational correlations. Source/version/coverage accompanies every report. This task authorizes local implementation and testing; production deployment and its database migration require separate authorization.
