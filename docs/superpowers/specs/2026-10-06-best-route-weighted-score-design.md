# 最佳线路 24 小时加权评分设计

## 目标

重新定义用户 Dashboard 的“最佳线路”：所有管理状态为 active 的线路进入候选，使用 24 小时监控快照，按请求成功率、缓存命中率和首字速度的加权总分选出每个 AI 工具的最佳线路。

## 候选范围

- 候选线路来自用户可见的线路列表，并只保留 `group.status === 'active'` 的线路。
- 是否已关联用户密钥不影响最佳线路候选资格。
- 按监控快照中的 `tool_ids` 将线路归入工具；没有显式映射时沿用现有平台回退映射。
- 非 active 线路继续显示在已关联线路区域，但不参与最佳线路评分。
- 后端原生监控快照生成覆盖所有 active 分组，不再受监控分组配置或工具映射过滤；接口继续保留原有用户可见权限。

## 数据窗口与指标

- Dashboard 加载 `getHybridPerformanceSnapshot('24h')` 作为最佳线路评分数据。
- 请求成功率使用真实请求计数：`real_success_count / real_request_count × 100`。
- 缓存命中率使用 `cache_hit_rate × 100`。
- 首字速度使用 `ttft_p50_ms`；值越小越好，在同一工具的 active 候选集合内归一化为 0–100 分：最快为 100，最慢为 0；所有有效线路首字相同则均为 100。

## 评分与选择

```text
总分 = 请求成功率分 × 0.5
     + 缓存命中率分 × 0.3
     + 首字速度分 × 0.2
```

只有三项数据均有效的线路参与最佳线路排名；active 线路仍进入统计列表，缺少指标的线路显示统计不足且不被选为最佳线路。缓存命中率为 `null` 或首字 P50 缺失视为指标无效。真实请求数为 0 时请求成功率无效。

总分相同时按以下顺序稳定排序：请求成功率高者、缓存命中率高者、首字 P50 低者、线路 ID 小者优先。

## 展示与兼容

- 工具卡片和详情中的最佳线路标签统一使用 24 小时评分结果。
- 成功读取 24h 详情时同步更新推荐；切换至 1h 或 7d 不改变推荐口径。
- 页面缓存同时保存推荐快照，返回页面时立即恢复尚未过期的推荐。
- 现有近 1 小时健康状态、线路检查、线路明细时间范围和已关联密钥列表保持原有行为。
- 24h 统计请求失败提供重试，并移除推荐；快照过期或没有真实请求时显示“暂无请求数据”。有真实请求但指标不全时显示“统计不足”。

## 验证

- 为评分函数添加单元测试，覆盖权重、TTFT 归一化、active 过滤、缺失指标和稳定并列排序。
- 为 Dashboard 添加集成测试，确认初次加载请求 24h、未关联但 active 的线路可成为最佳线路候选、停用线路不参与评分。

## 实现验证结果

- 前端模型、Dashboard 和监控接口契约：52 个测试通过。
- `pnpm typecheck` 通过。
- `go test -tags unit ./internal/service -run '^TestMonitorV4' -count=1` 通过。
- 本地候选实现，尚未推送、部署或线上验收；现有监控快照周期首次成功刷新后新增 active 线路的统计才会进入推荐。
