# 账号导入及授权后的双项检测准入

## 已确认要求
- 用户已确认 JSON 导入方案和鹈鹕沿用原生生成完成/HTML-SVG格式检查。
- 最新授权 UI 指令优先于此前草图：保持添加账号、第二步授权页面、页数、按钮、已有字段原样；只在第一步增加检测勾选框和勾选后必选的临时检测分组。目标组直接使用原有 group_ids，不新增或重命名目标分组控件。
- JSON 导入可选检测，检测组默认不分配；单独选择通过后的原生分组。
- 保存账号后立即后台运行糖果与鹈鹕各一次；必须同一轮双通过后才转入原生目标组。关闭页面不取消后台任务。
- 创建时即暂停调度且不得临时绑定默认组/目标组。未通过/超时保持隔离、保留记录，不删除账号。
- 参考流程的后续每10分钟复检纳入共享准入机制；明确失败退出本机制管理的正式组；传输故障不判定为降智。人工分组/调度修改优先，禁止任务覆盖人工修改。
- 账号密码沿用浏览器OAuth；不添加密码采集或自动登录页面。不修改普通续授权的分组语义。

## API 契约
- 共享可选字段：admission: { enabled: true, test_group_id?: number }。
- 所有原有 group_ids 都仍表示用户希望最终绑定的原生正式分组；后台保存目标快照，创建时只绑定临时组。
- /admin/accounts/data JSON 导入增加根级 group_ids?: number[] 和 admission；JSON允许省略 test_group_id。
- /admin/accounts/import/codex-session 同样视为JSON/凭据导入，admission可缺临时组。
- 原生账号创建/OAuth新增账号路径开启 admission 时必须有合法 test_group_id。未启用时不改变既有行为。
- 授权/JSON通用：临时组不得同时为正式组；必须有至少一个合法正式组，校验账号与分组平台兼容性、有效状态、重复ID。禁用检测时前端不发送 admission。
- 开启检测的重复JSON账号不静默摘掉在线账号：跳过该条并返回明确结果，由既有账号操作处理重检。

## 后台边界
- 复用 AccountTestService.RunPelicanBackground，糖果内置题及答案检查，鹈鹕现有完整SSE/非空/格式规则；不增加AI裁判。
- 模型沿用项目已有平台默认测试模型；每项一次，bounded concurrency，持久任务/租约保证多副本和重启可恢复。不能用浏览器请求生存期或无界goroutine管理任务。
- 保存结果和双项合取后，事务切换原生绑定并更新调度状态与scheduler outbox。任一任务不能单独启用账号。
- 避免默认组、simple模式、未分组池和旧自动恢复绕过准入。
- 自动处理需核验准入版本/凭据/绑定状态，人工改动优先；仅正常token刷新不重新建准入任务。
- 人工改组会取消自动任务的所有权；随后明确使用原生管理员调度开关启用时，取消准入托管并清理阻断，避免账号永久卡死。旧自动恢复入口没有此接管权限，仍受双项检测门禁约束。
- 检测/后台处理失败保留待处理数据；自动重试不得变成无限立即请求。后续周期复检继续使用同一任务身份。
- 授权失败不建账号；创建幂等重试不重复账号或检测任务；已消费授权码不重复兑换。

## 工作边界及验收
- 根目录main只读，不推送、不部署、不访问服务器/凭据、不发送真实模型请求。
- 独立分支由最新origin/main开始，承接本地main的18个既有依赖提交（189d2efb8a）；这些提交不属于本功能新增内容。
- 直接相关前端测试验证两字段、临时组必填、复用原group_ids、授权页结构不变、关闭开关旧payload不变、JSON可不分检测组。
- 后端测试覆盖原子隔离、双通过晋级、单项失败/超时、周期复检、过期租约/人工修改、不兼容分组、重复导入及幂等。
- 类型检查与相关后端包编译通过后交付本地候选，不声称线上DONE。
