# 调度恢复原生与现有改造收敛设计

日期：2026-09-19。状态：本地候选已实施验收；以本任务 evidence 为完成证据，未发布。

## 1. 目标与授权

用户接受恢复原生和修正现有改造，并于 2026-09-19 授权实施。允许本地开发、测试及任务提交；不合并、不推送、不部署或线上压测。不讨论或引入对原生的新增调度优化。

目标：退出自定义统一质量调度、请求驱动质量聚合及高成本完整事件观测；恢复已导入官方版本的普通文本调度链路，保留业务约束、协议兼容、计费和安全保护。

方案编写起点为 origin/main `aeebf865f453e3dca131119e3c67b7dfb0498153`。当前导入官方 v0.2.7，官方 commit `aea725f2ea644d5592d0bbb1d63b607efa7e200a`，记录见 `upstream/sub2api/XINGQIAO_UPSTREAM.md`。官方对象已获取并核实存在粘性选择、负载选择、Top-K 加权顺序。本轮没有重新查询生产版本，不能将本地版本等同于线上版本。前次审计针对 v0.2.4 的性能数字只作为复现线索。

## 2. 方案选择

选择“按功能恢复原生＋收敛观测消费者”。不选择仅关闭高级调度开关：质量刷新、事件记录另有独立入口。也不选择整文件覆盖或整站回退：当前 handler 包含后续协议、平台、计费适配。暂不选择修复并继续运行全部自定义评分：无法证明其收益，且仍保留复杂依赖。

“原生”是固定 v0.2.7 源码的行为契约，不是本地带有自定义修改但名字包含 native 的函数。实施前如果 main 的导入版本变化，先重做受影响差异表，不盲目降级。

## 3. 取舍与终态

| 范围 | 决定 | 终态 |
|---|---|---|
| 普通 OpenAI 文本统一评分选号 | 恢复原生 | 不调用 selectByUnifiedQuality；执行原生资格、协议绑定、粘性、负载与回退 |
| 冷启动/日常优先级加分、统一评分探索与特殊资源分层 | 退出自定义路径 | 原生账号/分组优先级及原生资源池回退生效；不提前丢弃空闲 API Key 池 |
| 请求完成后强制质量刷新 | 删除触发与 provider 装配 | 转发及管理页都不触发该整小时聚合；本轮不另建定时质量榜 |
| 五秒额外重试预算与故障域二次预算 | 退出额外准入控制 | 原生次数、原生超时与原生冷却行为决定尝试容量；安全重放保护仍可否决重试 |
| RetryNext 未处理状态 | 消除分支 | 完整恢复原生拿槽和错误语义；任何返回路径都有响应终态或客户端已取消 |
| 完整内存事件账本 | 删除运行态生产者与消费者依赖 | 不再保留每请求完整事件、不全局复制 4096 项 |
| 自定义全量调度日志 sink | 停止新写入 | 旧日志只读可查，明确停止采集时间/模式；不把旧数据当实时决策 |
| 旧调度日志保留期清理 | 修正现有实现 | 独立于写入 sink 启动；限定每轮耗时及条数，循环分批删除过期行并可取消 |
| 调度体验卡、自定义关联告警 | 停用依赖旧账本的项目 | 返回 unsupported/disabled 而非数值 0；规则不误触发、不误报恢复 |
| 基础监控、原生错误日志、usage、审计日志 | 保留 | 原生请求/错误/计费证据持续存在；不创建新指标平台 |
| 账号监控质量分/排序展示 | 调整现有页面 | 不再宣称自定义分数是运行排序；保留真实账号状态、用量、成本等独立数据 |
| 模型权限、平台/端点能力、利润终检 | 保留现有必要约束 | 无权/不支持请求不得转发；利润规则保持现有已授权语义 |
| 计费幂等、用量完整性、响应开始/副作用安全保护 | 保留并直接验证 | 不重复结算、不丢用量、不做不安全重放 |
| WebSocket、图片、非 OpenAI 平台 | 不切换算法 | 只适配共用接口；既有协议及额度修复不能被回退 |

利润策略本轮不重新定义软/硬门、不改变售价或倍率。删除自定义 unified 分区时，将原有已授权门及 bypass 语义在现有利润接口中保留，用固定用例证明。如果发现语义无法同时保持，列出具体冲突后取得范围调整，不能悄悄放开或收紧。

共享健康、故障域、临时冷却不整套删除：逐项区分原生资格/冷却、特定已验证安全修复、自定义质量排名和重复预算；仅后两者退出普通文本运行控制。审计尚未证明所有共享健康逻辑都应删除。

## 4. 目标请求流程

权限和模型校验 → 原生协议绑定/粘性/负载选择（保留本站能力及利润资格约束）→ 原生原子并发槽与有界等待 → 保留利润终检 → 上游转发 → 原生尝试上限与已保留安全重放条件 → 原有用量/计费/错误记录。

请求及完成路径均不计算历史质量榜，不向自定义完整事件账本或全量调度日志队列写入。客户端取消、响应开始、工具副作用、已知用量等安全条件优先于任何重试机会。管理页面不能再通过打开排名卡片把已退出的质量聚合重新启动。

## 5. 数据与配置兼容

不删除数据库表、列或既有设置，不新增 schema migration，不重写余额、用量、账号组关系。旧评分、权重、探索设置原值保留供回滚，但普通文本不再使用退休参数；专用协议的既有读取保留，界面说明范围且不开放这七项退休参数编辑。原生支持且仍有效的参数不能一并禁用。

历史日志查询接口继续工作；新增采集状态为响应中的可选兼容字段，前后端同版本交付。配置写接口对已停用参数明确拒绝并说明原因，不“保存成功但不生效”。历史配置不在服务启动时批量迁移。

旧日志清理默认每轮最多 10,000 行、每批 1,000 行、轮次 60 秒、上下文最多 2 秒；只清理超过原有 7 天期限的数据，失败下轮再做。该数值是清理旧积压的保守实施起点，不是承诺高 RPM 持续写入能力；最终已停止新增该类日志。清理须限定到现有请求侧角色，不让 worker/探测器重复启动。

## 6. 交付和验收原则

一条功能分支、一个写入者，按可验证任务提交，所有相关终态完整后形成一个发布候选。中间提交不单独部署，避免 UI、告警和运行态分离。只做直接相关测试及受控本地/隔离环境复现，不访问真实付费上游、不在生产压测。

必过：首次等待超过五秒后仍能合法转发；满队列/Redis 错误/超时有明确响应；粘性与负载回退符合固定原生版本；成功完成不再触发质量 SQL；并发事件写入不再存在整表复制；历史日志可读且清理有界；退出指标显示不可用；计费、安全与协议保护不退化。

复用无变化部分的有效证据。新测试只对真实行为和跨模块契约断言，不以 Contains 函数名充当功能验证。局部压力只证明本次固定开销移除和饱和正确性，不宣布全站最大 RPM。

## 7. 发布与回滚边界

当前不执行发布。未来明确授权后遵循根 AGENTS.md：已推送干净 main 为来源、应用构建采用蓝绿、保持旧服务至新服务就绪，切流后最长 300 秒排空旧请求，验证失败恢复旧路由。测试站非必经步骤。数据库 schema 不变，正常候选无需迁移；若实现发现必须新增迁移，先变更方案及发布范围。

回滚使用旧版本制品与路由，保留原设置及表；新版本不重写旧评分参数。已超过保留期被正常清理的历史日志不可恢复，不应承诺回滚能恢复这些日志。不得回滚余额或覆盖恢复流量后新增用量。


续接说明：原仓库已隐藏整块旧调度设置面板，本任务保留此状态，原生参数继续通过原有 API 生效，不为恢复编辑控件新建页面。候选验证范围、样本缩减和已核实基线失败见实施 evidence。
