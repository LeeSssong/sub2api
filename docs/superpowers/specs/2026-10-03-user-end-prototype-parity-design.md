# 用户端 UX Prototype 与测试站一致性复刻规格

## 目标

将 `ux-prototype` 做成测试站用户端的可交互镜像：页面、弹窗、文案、数据状态、操作路径、错误与空状态、桌面/移动端布局均以 `upstream/sub2api/frontend` 当前实现为事实源。原型中的示例数据只保留为离线演示适配层，不改变页面结构和状态语义。

## 页面范围

- AI 工具：工具卡片、线路详情、创建密钥、关联密钥、我的 AI 线路、检查线路。
- 使用记录：时间范围、统计粒度、概览、分布图、Token 趋势、用量明细、错误请求、请求详情、列设置、筛选和导出反馈。
- 我的密钥：工具栏、筛选、端点、列设置、创建/编辑密钥、线路切换、使用方式、导入 CCS、启用/禁用、删除确认。
- 充值与兑换：充值、兑换码、支付方式、订单承接、恢复/取消、结果与错误态。
- 我的订单：筛选、分页、详情、恢复支付、取消确认及终态。
- 个人资料：头像、用户名、邮箱、密码、额度提醒、安全设置、Passkey、客服。
- 共用壳层：品牌、侧栏、余额、用户菜单、客服弹窗、加载/失败/空状态、Toast 与响应式布局。

## 实现边界

- 原型使用独立静态运行时，不调用测试站真实账号、密钥、支付或敏感接口。
- 页面 DOM、可访问名称、交互顺序和状态文案与当前前端保持同构；演示数据通过 model 层注入。
- 参考当前前端路由、组件和现有 `ux-prototype-source.tar.gz`，避免重新发明平行信息架构。
- 不修改测试站部署、账号、数据或生产发布链。

## 验证

- 原型单元测试覆盖页面渲染、弹窗打开/关闭、表单错误保留、确认操作和状态切换。
- 运行原型测试与前端相关测试。
- 浏览器验证桌面宽度和 390px 移动宽度，逐页检查页面与弹窗可达性、无水平溢出和关键状态。
- 运行 Impeccable detector，记录并处理机械性问题。
