复核时间：2026-09-27。状态：`/usage` 本地候选已调整，**未合并、推送或部署；整版验收未通过**。冻结基线为 `artifacts/opt-003-v02-baseline/ux-prototype-source.tar.gz`，SHA-256 `5a0beaa34e13f014513d5dd8ffe9a8a13bf7bcd5f381217fc4a2604bd04fa68c`，主要截图 `prototype-usage-{1280,390}.png`。用户附图是测试站与 UX Prototype 的同屏截取，但图像物理像素不直接等于 CSS 视口；本轮核对采用冻结的 1280×900、390×844。

## 已确认的实现偏差

用户附图和测试站当前 `/usage` 的代码一致：统计是四张独立卡，日期/粒度在另一个卡片中，四个图表有间距且各自带边框；原型将日期/粒度与统计放在同一连续概览面板，图表位于一个 2×2 连续分析面板，内侧以细分隔线区分。原型后续源文件明确使用 `.usage-overview`、`.usage-analysis`、`.usage-records` 三个工作面。此前验收文档只核对标题与部分局部失败态，没有覆盖此视觉结构，不能据“标题一致”推论页面一致。

本地候选 `codex/opt003-usage-prototype-layout` 将 `/usage` 分成三个工作面；复用真实日期、统计、图表、筛选、明细组件，局部取消它们在用户页的独立卡片外观；第二个图表改为“线路使用分布”，记录区增加“请求明细”。共享图表在后台默认仍称“分组使用分布”。真实 `$` 金额格式、按真实接口显示的余额、空态、错误告警与局部刷新没有替换成原型 Mock。原型的 `$30.00`、模拟请求和趋势不属于测试站数据要求。

本次补充核对用户提供的筛选区双图：原型初始普通记录仅有 **API 密钥、模型、线路、计费模式** 四列，默认展示“全部密钥／全部模型／全部线路／全部计费模式”；刷新、重置、列设置靠左，导出 CSV 靠右。此前候选把七项筛选直接铺成两行，前三项显示“请选择”，且全部操作靠右，属于**实现偏差**。初次改为四项时额外加入“更多筛选”，并沿用全站灰色下拉、浅色导出按钮与较大的操作按钮，用户新附图指出仍不一致。最新候选撤下这个入口，只保留原型四项主筛选；请求类别、压缩、计费类型不再可从用户页设置，默认值和重置逻辑仍是未筛选。这是**待确认取舍**，不可把三项筛选能力的减少视为已获单独验收。记录区域局部覆盖品牌下拉背景、边框、标签和操作按钮尺寸/颜色，以匹配原型的深色紧凑样式。错误请求 tab 的独立筛选保持原样。

用户随后对比概览区双图：本地候选的日期选择器带日历图标且较高、粒度标题是“粒度”、四项统计分隔线贯穿整个高度、总消费为绿色并划去标准价、空请求平均耗时显示 `0ms`；原型使用紧凑深色控件和“统计粒度”，分隔线在统计单元内缩，总消费为中性色且标准价不划线，零请求耗时显示“—”并有“当前筛选范围”。这些均标为**实现偏差**。候选现在仅在用户概览启用空耗时状态与副标题，真实非零耗时不变；仅局部调整日期/粒度与统计外观，不影响后台统计卡默认展示。附图的标题在本地预览顶部被截断，视口和滚动位置未明确锁定，不据此单独判定页面水平边距实现有误。
