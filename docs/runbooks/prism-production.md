# Prism runtime on the production Docker host

Prism uses the existing official `upstream/sub2api/prism-adapter` source and pinned Python wheels. Install those files from the clean, pushed main source into a versioned `/opt/sub2api-prism/releases/<commit>` directory. `/opt/sub2api-prism/current` selects that version; the shared Python environment and matching prebuilt Chromium live under `runtime/`. No application source build is needed.

The gateway accepts only a numeric loopback adapter URL. Each running blue, green or worker container therefore receives a host systemd adapter in its network namespace. `ops/sub2api-prism-reconcile.py` follows container replacement using inspected IDs/PIDs, rejects other Compose projects, and only manages Prism units. It never starts, stops or recreates an application container. A 10-second systemd timer maintains bindings across subsequent releases. The adapter's `/health` endpoint is on port 8319; Responses is `/v1/responses`.

All adapters run as `sub2api-prism` with Chromium sandbox enabled. The aggregate `sub2api-prism.slice` limits them to one CPU, 900 MiB memory, no swap and 256 tasks. Browser runtime files are root owned; writable state is private to each slot. The sandbox helper is root owned mode 4755. The service uses host upstream DNS configuration inside the container network namespace.

The root-owned `/etc/sub2api-prism.env` (0600) contains the bridge key, browser paths and adapter settings. Gateway keys go in the protected production configuration only. Enable `GATEWAY_PRISM_BROWSER_ENABLED`, set `GATEWAY_PRISM_BROWSER_BASE_URL=http://127.0.0.1:8319/v1` and set its API key to the adapter key for API services. Changing gateway environment requires a normal blue/green promotion, preserving the existing worker unless a worker update is separately needed. Reuse the verified existing application image with its original source identity when only installing this external runtime.

Start with serialized browser mode and one cached context per adapter. Account switches stay as configured; installing the runtime does not automatically reroute customer accounts. Verify unit tests, real sandboxed Chromium against the upstream synthetic fixture, adapter authentication from the API namespace, then the normal application health/version checks. Health alone does not verify OAuth/model availability. An actual authorized account test is necessary before declaring the Prism upstream usable.

Rollback the gateway through the existing release record. Stop the reconciliation timer and individual Prism units to disable the external runtime; preserve pending state and any tools database. Never delete pending files to bypass unknown upstream outcomes. The official adapter remains experimental and does not expose authoritative usage for billing.
