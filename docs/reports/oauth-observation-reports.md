# OAuth observation reports

`oauth-observation-reports.sql` is an executable, read-only psql report. Use an authorized database connection through a protected PostgreSQL service configuration (`PGSERVICE`) or the normal PostgreSQL environment. Do not put credentials into this file or a command-line connection URL.

```sh
PGSERVICE=sub2api-readonly psql -X -v ON_ERROR_STOP=1 \
  -v from='2026-10-02T00:00:00+08:00' -v to='2026-10-03T00:00:00+08:00' \
  -v account_id=0 -f docs/reports/oauth-observation-reports.sql
```

`account_id=0` means all observed accounts; an individual account ID restricts the report. Defaults are the last day/all accounts. Windows must be positive and no longer than seven days. Timeline and archive sections show the first 5,000 matching events; the complete data remains queryable. Current account names are resolved through an authorized join, never copied to telemetry. Deleted rows may have no display name.

The **primary account lifetime** is the first healthy native state probe to the first subsequent degraded state probe across models. Detailed model/protocol/probe-version projections are also retained. Inconclusive/network failures, expiry, manual disable, quota and BPS changes never terminate lifetime; recovery never resets it. Before a healthy probe, state is `not_started`. Without a later degraded probe, state is `no_degraded_observed`, not an assertion of present health. `last_probe_at` shows observation freshness. Lifetime rows show the currently retained endpoints; the selected window filters the accompanying activity, not a historical as-of reconstruction. Cohort median covers only ended episodes and is explicitly not a survival-adjusted estimate.

Each account database record is an episode. Reimported records link by HMAC of stable ChatGPT user/workspace identity where both exist. Missing identity remains unlinked. Changing upstream identity in an existing row flags `identity_conflict`; such rows are excluded from cohort conclusions. Do not overwrite identities to reuse episodes. The random HMAC secret is generated once inside the database, denied to PUBLIC, and must travel with database backups; it is not a credential and is never printed. Migration requires permission to install the standard PostgreSQL pgcrypto extension. Runtime and migration normally use the owning database role; explicitly grant helper execution only if using a separate runtime role.

Traffic amounts are copied from native usage logs: `total_cost` is standard USD and `actual_cost` is site charge. They are observation facts, not another billing ledger. Minute facts reconcile native INSERT/UPDATE corrections; deleting source logs retains observations until their own retention deadline. Protocol follows the actual upstream endpoint (BPS/native/Live/unknown). Missing durations and incomplete token reports remain marked. Costs during healthy lifetime use exact source timestamps; no synthetic $450 quota is assumed.

Slot acquisition/release records span all application instances. The occupancy report splits intervals across minute boundaries and computes time-weighted average, peak and saturation against a consistently observed slot limit. Live admission reservations are retained but excluded to avoid double-counting the Live lease. Unreleased, release-failed or lease-expired intervals are incomplete: average/peak are NULL, and occupied seconds are an estimate up to the recorded expiry. With telemetry loss, even closed-slot metrics are observed values, not a guarantee of complete global occupancy. Queue enter/leave counts have no known initial baseline and do not pretend to be exact queue length.

An internal server-generated attempt ID links selection, slots, fallback and outcomes for an HTTP request or WebSocket turn. An outcome is an attempt observation, not a billed-request count; success observations and native usage facts must not be added together. Probe events carry the scheduled rule/round when available, and operational snapshots record quality-policy provenance or `unknown`. Admin audit is explicitly post-hoc and does not claim its account snapshot was taken at the exact mutation instant. Free-text upstream errors, prompt/answer text, tokens, tickets, emails and client identifiers are excluded.

Runtime queue capacity is 4096, batch size 128, flush interval one second, and each write has a two-second timeout with up to three idempotent attempts. Saturation/failure never changes inference results. Probe results get bounded synchronous persistence with queue fallback. Delivery failures are visible in instance health and structured warnings; health history is sampled every ten seconds into minute records. Counters include submissions filtered out as non-OAuth and count delivered batches, not distinct stored OAuth events. Missing intervals and stale heartbeat data mean unknown coverage. Shutdown cancels pending writes at its deadline and accounts for abandoned events.

Events, slots, configuration/quality archives and health history retain 90 days; usage contributions and minutes retain 180 days; compact lifetime/identity summaries survive pruning. Cleanup deletes at most 5,000 rows per table per minute per instance. Old raw details cannot be reconstructed from summaries. No missing historical OAuth quality results are fabricated or backfilled. All observations begin when the migration and new runtime are deployed. These reports describe associations, not proof that concurrency or a model caused quality changes.
